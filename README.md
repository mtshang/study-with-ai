# Study with AI

以独立课程为单位的全栈多 Agent 教学系统，使用 React、Python + FastAPI、MySQL、LangChain 和 LangGraph。

当前已实现账号、个人课程、章节与路线版本、练习/作业发布和提交、客观题核对、资料上传下载以及账号显示设置。后端已拆为账号、教学业务、AI 三个服务，通过统一入口访问。**已接入个人模型配置、课程聊天、流式显示、停止回复和受控练习和作业发布。已支持教师动态委派助教、结果暂存与暂停/恢复；已支持新提交的单道开放练习自动批改和教师讲解；已支持多题作业逐题批改，以及课程资料读取与基于资料讲解、出题；作业附件仍待评阅。**

## 架构

```text
React :5173
  │ /api（开发时由 Vite 转发）
  ▼
开发 HTTP 入口 :8000
  ├─ /api/auth/*、/api/preferences/* → 账号服务 :8001 → study_identity
  ├─ /api/courses/*                 → 教学业务服务 :8002 → study_learning
  └─ /api/ai/*                      → AI 服务 :8003 → study_ai
                                      └─ HTTP → 教学业务服务
教学业务 / AI 服务 ──内部 HTTP──► 代码执行服务 :8004 ──► 临时 Python 容器
教学业务 / AI 服务 ──会话验证 HTTP──► 账号服务
```

三个数据库可部署在同一套云端 MySQL 实例，分别使用专用账号；服务不能直接访问其他服务的数据表。本机 Docker MySQL 用于模拟部署环境。原 `study_with_ai` 数据库在本次迁移中保留；新服务不会继续写入旧库。

入口使用现有 FastAPI/httpx 实现开发代理，处理固定路径路由、错误和响应流转发，不拥有业务数据。它不是完成公网加固的生产网关；目前全部监听本机地址，TLS、生产反向代理、部署配置和跨主机服务身份仍需完善。

每个业务服务内部按 `api → services → repositories` 分层：接口层处理 HTTP，业务层执行规则和事务，数据访问层执行查询和写入。`models` 为表模型，`schemas` 为接口数据结构，`infrastructure` 为数据库与文件支持，`clients` 为跨服务请求。数据库模型字段的修改与事务提交仍由业务操作组织。

### AI 内部运行框架

教师的状态刷新、模型调用和工具执行由 LangGraph 状态图组织；教师、助教及批改通过 LangChain 模型适配器接入现有受控流式客户端。账号、教学与执行服务边界不变，审批、课程版本和暂停规则继续由应用服务校验。

已接入 MySQL 任务持久化、LangGraph 图检查点与步骤收据。原登录会话有效且未暂停的安全任务可在重启后恢复，最多自动恢复两次；流式中断保留草稿并重试未完成轮次。课程结构化内部记忆已接入；用户 Skill/HTTP MCP 与 Agent 隔离执行、生成产物已接入。默认不向外部追踪平台发送运行数据。 教师与动态助教结束回复前会核对操作声明与工具执行记录；不一致时允许一次纠正，仍不一致则标记未完成。核对会增加模型调用，不能替代后端权限校验或保证所有回答正确。

## 本地启动（Windows PowerShell）

需要 Node.js 22.12+、Python 3.12、Docker Desktop（Linux 容器）。不要覆盖已有 `.env` 或 `.env.services`。

首次使用先复制根目录 `.env.example` 为 `.env`，填写两组不同的随机数据库密码，然后：

```powershell
cd D:\项目\study-with-ai
docker compose up -d --wait mysql
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe scripts/init_service_databases.py
.\.venv\Scripts\python.exe scripts/migrate_services.py
```

已有环境不需要重复创建虚拟环境。初始化脚本只适用于本项目的本机 Docker MySQL，生成被 Git 忽略的 `.env.services` 和三个专用数据库账号；已有配置和密码不覆盖。云端部署请由数据库管理员配置对应库和授权。

日常在一个终端启动入口和全部服务：

```powershell
cd D:\项目\study-with-ai\backend
.\.venv\Scripts\python.exe scripts/run_services.py
```

脚本启动五个独立进程（入口、账号、教学、AI、代码执行），Ctrl+C停止这一组进程；核心四进程之一退出会停止其余进程，代码执行服务单独退出不停止普通业务。这是开发启动器行为，不代表线上服务必须一起停止。原来的 `uvicorn app.main:app` 现在仅启动入口，不能代替这个命令。

另一个终端启动前端：

```powershell
cd D:\项目\study-with-ai\frontend
npm.cmd ci
npm.cmd run dev
```

打开 **http://127.0.0.1:5173**。日常无需重复 `npm ci`。关闭网页不停止服务。`docker compose stop mysql` 停止数据库并保留数据。遇到端口占用，先核实已有进程，不要盲目重复启动或结束其他程序。

服务也可分别用 `uvicorn services.identity_service.main:app --port 8001`、`services.learning_service.main:app --port 8002`、`services.ai_service.main:app --port 8003` 和 `gateway.main:app --port 8000` 启动，均需绑定 `127.0.0.1`、关闭代理头信任。依赖都在 `backend/.venv` 中。

## 当前业务能力

- 注册、登录、退出和会话撤销；密码用 Argon2id 哈希，会话凭证只保存哈希。Cookie 使用 HttpOnly、SameSite=Strict，开发环境允许本机 HTTP。
- 课程新建、编辑、归档和恢复；章节内容、顺序、阅读状态、当前章节；历史路线快照保留。章节使用归档而非直接删除。
- 课程版本检查防止旧页面覆盖新修改。同一次课程创建、作业发布、答案提交和资料上传的重试按请求 ID 去重；同 ID 不同内容返回冲突。
- 练习一道题，作业 2–10 道题；判断、单选、开放问答。单选逐个添加 A–J（2–10 项），每项最多 200 字符，删除后字母与答案对应关系同步更新。
- 客观题由后端核对，读取题目时不泄漏参考答案；新提交的开放练习和作业文字答案由 AI 批改，附件仍待评阅。每次提交保留答案、题目快照和结果，发布后暂不编辑原题；支持移入回收站及用户永久删除，提交历史保留。
- 资料支持笔记、HTTP(S) 链接、每份最多 10 MiB 的文件上传下载。文件使用 UUID 存储，下载验证课程归属。链接不会自动抓取，文件不在网页内执行；教师可按需读取支持格式的文字内容。
- 作业可关联本课程最多 5 份已上传文件；历史附件仅引用当时的名称；用户删除原资料后不能下载，不保留副本。练习暂不附带文件，附件不能替代必答题。
- 账号显示设置包含字号增量 0–6px（默认 3）和紧凑布局，保存在账号 `settings.json`，带版本检查，不覆盖其他设置字段。

课程 API 暂时针对小规模原型：每门最多 100 章节，正文最多 20,000 字符；保存整门章节结构，页面加载最近 100 个版本摘要。练习、提交与资料仍随课程读取，尚未做全面分页。

登录后进入真实个人空间；未登录时可查看独立本地演示。演示数据使用浏览器 localStorage，不是私人资料存储，也不会自动迁移到账号。个人课程正文不存 localStorage。普通保存失败保留表单草稿；刷新、离开页面不保证保留未提交内容。

## 技能、MCP 和 AI 边界

技能页面提供名称、拖拽、ZIP/文件夹选择；MCP 页面提供名称、JSON 行号、格式化和基础字段检查。示例为 [官方 Everything 的 Windows stdio 配置](https://github.com/modelcontextprotocol/servers/tree/main/src/everything#usage-with-claude-desktop-uses-stdio-transport)，`mcpServers` 不代表所有客户端统一的配置格式。

这些是早期界面设计说明。当前已实现技能导入、后端持久化、逐课程启用及 HTTP MCP 调用；实际支持范围见下文“用户技能与 HTTP MCP”。

AI 导师支持真实课程聊天、读取当前课程、发布练习或多题作业，以及异步委派只交结果的助教。完全手动模式需批准草稿；部分批准和完全访问允许当前已开放的练习和作业发布工具直接执行。教学服务负责权限、版本与幂等校验。聊天记录、运行状态和提议保存在 AI 数据库。

关闭页面只断开显示订阅，后台回复继续；停止生成取消本轮并保留部分文字，不撤回已发布练习。当前单个 AI 服务进程内运行后台协程；已入队任务按下述恢复规则处理进程中断。每课程同时一轮、四个执行槽、五分钟/六轮模型调用上限，历史上下文有限裁剪。助教异步协作见下文；尚未实现专业任务队列、附件批改、RAG或视频生成；学生Python练习已通过独立容器执行，见下文。

### 个人模型配置

登录后在设置顶部切换“聊天模型”“视觉模型”，分别配置 Key、基础地址、模型名称。也可编辑本人用户目录的 `.env`：

```dotenv
CHAT_API_KEY="填写自己的 Key"
CHAT_BASE_URL="https://api.deepseek.com"
CHAT_MODEL="填写模型标识"
VISION_API_KEY="填写自己的 Key"
VISION_BASE_URL="https://api.deepseek.com"
VISION_MODEL="填写模型标识"
```

个人配置不注入进程全局环境，不回显旧 Key；留空保留，明确清除才移除。更换地址时须重填或清除 Key。接口使用 HTTPS 的 Chat Completions 格式；实际验证供应商为 DeepSeek。视觉分页支持合成图片连接测试，课程图片上传问答尚未开放。测试连接会发起付费供应商请求。普通账号、课程业务不依赖模型密钥。

## 变更顺序与工具接口

教学库中的 `course_revisions` 保留课程/章节快照；新增 `course_changes` 记录课程、活动、提交、资料的操作顺序。每门课程有独立递增 `sequence`，和业务变更在同一事务保存；UTC 时间戳辅助展示，不作为严格排序依据。重试和无变化保存不会重复产生变更。

迁移课程从 sequence=1 的当前状态基线开始；旧路线版本原样保留，不伪造过去未记录的事件。

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 入口存活 |
| `GET /api/ready` | 三个服务及各自数据库就绪情况 |
| `/api/auth/register、login、me、logout` | 账号功能，沿用原请求方式 |
| `GET/PUT /api/preferences/display` | 账号显示设置 |
| `GET/POST /api/courses` | 列表、新建 |
| `GET/PUT /api/courses/{id}` | 读取、保存课程 |
| `GET /api/courses/{id}/revisions/{version}` | 旧版课程快照 |
| `POST /api/courses/{id}/activities` | 发布练习或作业 |
| `POST/GET /api/courses/{id}/activities/{activity_id}/submissions` | 提交、历史 |
| `POST /api/courses/{id}/materials` | 笔记或链接 |
| `POST /api/courses/{id}/materials/upload` | multipart 文件上传 |
| `GET /api/courses/{id}/materials/{material_id}/download` | 下载 |
| `GET /api/courses/{id}/changes?after=0&limit=100` | 按序号读取变更；上限 200，返回游标与当前水位 |
| `GET /api/courses/{id}/context` | 当前课程、课程版本、变更序号 |
| `GET/PUT /api/ai/config` | 本人的聊天/视觉模型设置与审批模式，Key 不回显 |
| `POST /api/ai/config/{chat或vision}/test` | 测试已保存的模型连接 |
| `GET/POST /api/ai/courses/{id}/runs` | 最近聊天轮次、创建后台回复 |
| `GET /api/ai/runs/{id}/events` | SSE 回复快照，断开不取消任务 |
| `POST /api/ai/runs/{id}/stop` | 停止教师当前回复并暂停本课程自动唤醒 |
| `GET /api/ai/courses/{id}/agents` | 助教状态、待处理数量及结果 |
| `POST /api/ai/courses/{id}/pause` | 包括仅助教运行时的课程暂停 |

| `POST /api/ai/courses/{id}/submissions/{submission_id}/grade` | 启动、核对或重试批改，同次提交幂等 |
| `GET /api/ai/status` | 已登录用户查看 AI 接入状态 |
| `GET /api/ai/courses/{id}/context` | AI 服务通过 HTTP 读取教学服务上下文 |

教师每轮先按课程变更序号读取到固定水位，再接收助教结果，并将通知存入持久化上下文。发布前仍需读取最新课程，并由教学服务检查版本。新修改不会因为已经发送通知就自动失效。

## 教师与助教

在课程聊天中可要求教师委派助教准备题目、解释或总结，并让教师继续讲解。教师编写角色和任务，助教独立请求当前用户的聊天模型，只返回结果。是否发布练习仍由教师及审批规则决定。

教师或助教工作时可停止：停止教师当前回复并暂停自动唤醒，助教继续完成。结果存数据库并生成课程内的暂存文档；再发消息或点击“继续处理结果”即可读取。已领取通知与教师上下文同事务保存，只删除已确认文件。

当前是单 AI 进程内的异步任务，不是独立助教微服务。每轮最多委派三个、每课程最多同时三个助教；教师和助教各最多四个并行执行，单任务五分钟上限。自动结果整理轮不能再次委派。服务重启后可恢复已入队任务；已完成模型步骤复用，未完成轮次可能重新调用。完成结果保留并补发通知；用户暂停与原会话失效均阻止自动唤醒。不要为当前 AI 服务启用多个 workers。

最新迁移为教学 `0002_learning_grading` 与 AI `0004_ai_grading`；已有环境启动前运行 `scripts/migrate_services.py`。迁移不重建用户或课程，也不自动批改历史提交。

## 开放练习自动批改

新提交的单道开放练习会自动调用聊天模型，给出基本掌握 / 部分掌握 / 需要再练、理由、答案原文依据、改进建议和参考解释。客观题仍由后端按固定答案核对；多题作业采用下述逐题流程；附件与代码运行不在此范围。评价仅针对本次答案，不代表整门课程完成。

题目、答案和参考解析按提交时的快照保存，重新作答保留旧记录。结果校验后写入教学数据库，并交给教师继续讲解；暂停课程只保留结果，不自动唤醒教师。模型设置缺失或网络失败不撤销已提交答案，可在提交反馈/历史中点击重试。

AI 已生成的有效评价先存入数据库；回传失败时重试补存原结果，不重复生成。教学提交到首次创建 AI 批改任务的通知仍是即时尝试，若在任务入队前退出，需用户点重试；已入队任务和已保存的助教结果按持久恢复规则处理。

## 身份与数据边界

教学服务和 AI 服务通过账号服务的内部接口验证会话，不直接查账号库。内部接口需要服务凭证，统一入口不对外转发它。客户端传入的用户 ID 不作为登录凭据。`X-Workspace-User` 用于防止换账号后的旧页面误写，必须与真实会话身份一致。

账号服务不可用时，其余服务的受保护操作会失败关闭；没有增加身份缓存。当前基础限流仍在账号进程内，经过开发代理时按代理来源合并计数，尚未实现面向真实客户端 IP 的分布式限流。服务间凭证为开发配置，生产环境需进一步做独立身份、网络隔离和轮换。

前端写请求必须携带允许的 Origin；默认 5173/5174。各服务 `/docs` 可查看接口，但直接在服务端口执行写请求仍会受到 Origin 限制。公开部署需 HTTPS、`COOKIE_SECURE=true` 和准确的来源配置。

```text
backend/
  gateway/                       开发 HTTP 入口
  common/                        通用配置、错误、会话客户端与基础设施工具
  services/
    identity_service/            账号、会话与个人显示设置
    learning_service/            教学业务与有序变更
    ai_service/                  个人模型、课程聊天和受控练习工具
      api/ services/ repositories/ models/ schemas/
      clients/ infrastructure/ migrations/ alembic.ini
  scripts/run_services.py        启动四进程
  scripts/migrate_services.py     各服务独立迁移
  tests/                         分层业务回归与入口测试
resources/                       系统资源占位
user_data/u_<安全前缀>--<UUID>/
  user.json                      辅助映射，不是身份授权依据
  settings.json                  账号显示设置
  .env                           个人 CHAT_* / VISION_* 模型配置
  api/、skill_mcp/               多供应商配置与技能连接器扩展预留
  courses/<课程UUID>/materials/  已上传课程文件
  courses/<课程UUID>/assistant_inbox/  带助教 ID 的未确认结果副本
```

当前服务仍共享同一个后端文件根目录，按职责使用不同区域；这是本机部署约束，不是已完成的跨机器文件存储。用户文件在服务端，不是浏览器电脑上的离线副本。个人 `.env` 不会加载到服务器全局环境。文件写入与 MySQL 事务之间仍使用普通失败补偿，进程崩溃残留需核对，备份必须同时包含数据库和文件。

## 验证（本地开发记录）

本仓库按发布范围不包含测试源码、测试配置或验收脚本；以下测试命令仅适用于保留完整测试文件的本地开发副本，不能在仅克隆公开源码后直接复现。运行项目所需的初始化、迁移和启动脚本仍保留。

```powershell
cd D:\项目\study-with-ai\backend
.\.venv\Scripts\python.exe scripts/init_service_databases.py --test
$env:SERVER_ENV_FILE = "D:\项目\study-with-ai\.env.services.test"
try {
  .\.venv\Scripts\python.exe scripts/migrate_services.py
  .\.venv\Scripts\python.exe -m pytest -q
} finally {

}
```

测试只允许 `study_identity_test`、`study_learning_test`、`study_ai_test`，会删除其中测试记录。禁止改成正常业务库。业务回归使用测试组合入口，验证分层规则；跨进程行为另由下面的集成测试验证。
